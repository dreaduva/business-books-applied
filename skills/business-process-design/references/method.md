# Repeatable Process Brief: Method and Judgment

## Start with the current task

A procedure based only on an ideal workflow can miss the decisions that make real work succeed. Separate observed steps from proposed improvements. Ask for an example of a difficult case when that information would change the exception path.

## Define completion externally

“Operator finished the checklist” is weaker than “customer can perform the required action.” Choose acceptance evidence appropriate to the process. A support response being sent does not necessarily mean the issue is resolved.

## Make escalation usable

Name a role, the information it needs, and what pauses while waiting. If the owner is unknown, retain that gap rather than pretending the workflow is ready for unattended operation. Do not place passwords or customer data in the document.

## Review for learning

Measure rework, missed handoffs, and ambiguity as well as speed. A faster process that creates more failures is not necessarily better. Keep version and review ownership lightweight. A fictional desk test can illustrate a revision, but it cannot establish operational reliability.

# $100M Leads Worked Example: From Downloads to Relevant Conversations

**Fictional teaching example.** All people, messages, counts and outcomes are invented. No outreach was sent and no real campaign is reported.

## Campaign A: the broad resource

LessonLoop is a manual lesson-change tracker. Its founder can handle four 15-minute product conversations in the next week and has two hours for campaign administration. The offer is a prototype walkthrough, not a promise of automated scheduling. Distribution is a proposed approved post in a tutor community; moderator permission is assumed only within this fictional scenario.

Initial resource title: “A weekly productivity checklist.” Its final paragraph invites a product walkthrough. That broad title is easy to promote but does not select for tutors handling lesson changes.

Predefined fit rule: an independent tutor who personally handles lesson changes, had at least three in the last month and is willing to discuss the current workflow. Requesting a call and meeting this rule are separate facts.

## Fictional event record

During the seven-day campaign, 200 distinct tracked visitors reach the resource and 100 open it. Eight unique people explicitly request a conversation. IDs below represent all eight requests; the example does not claim to know the roles of the other 92 openers.

All eight requesters received a fit assessment. L07's qualification does not imply a completed interaction. The table preserves a delivery failure separately from a customer decision.

## Funnel with named denominators

- Resource opens per tracked visitor: 100/200 = 50%.
- Conversation requests per resource opener: 8/100 = 8%.
- Qualified requests per request: 3/8 = 37.5%.
- Qualified requests per opener: 3/100 = 3%.
- Held conversations per qualified request so far: 1/3; one no-show and one pending owner response.
- Sales: not measured by this prototype campaign. A walkthrough is not a purchase.

The headline “100 new leads” conceals most of what the team needs to know. The eight requester roles suggest the resource may be too broad, but the campaign does not establish the role distribution of all openers. The delayed reply is a separate problem even if the resource changes.

## Decision: narrow the resource, repair the handoff

The founder chooses content in the same community rather than adding paid distribution. The next resource targets the actual work: “Which changed lessons still need a reply?” The distribution context stays the same where permission allows, so the team can inspect whether clearer relevance improves the incoming requests.

Repairing L07's missed handoff is necessary service work, not a variable to leave broken for experimental purity. The next report must acknowledge that both the resource and response process changed; it cannot attribute all differences to the new title.

## Campaign B: the complete resource

### Which changed lessons still need a reply?

A quick worksheet for independent tutors arranging changed lesson times through messages.

1. List each changed lesson you are currently tracking. Use a student label rather than sensitive details.
2. Record the new time and where the conversation is taking place.
3. Mark whether you have a reply confirming the change. Use “unknown” if you have not checked.
4. Review the pending rows before deciding what needs a follow-up. Update the list when a reply arrives.

| Student label | Changed time | Conversation location | Confirmation status | Next action |
| --- | --- | --- | --- | --- |
| Example A | Thursday 16:00 | Messaging app | Pending | Check thread before following up |
| Example B | Friday 10:00 | Email | Confirmed | None |
| Your row | | | | |

This list does not read messages or send reminders. It helps you keep track of what you have checked.

**Optional next step:** If you handle several changed lessons and want to see a manual tracker for maintaining this list, request a 15-minute LessonLoop prototype walkthrough. The worksheet is usable without requesting a call.

## Distribution and reply drafts

**Community post:** “If you arrange changed lessons through messages, this one-page worksheet helps you list which changes still need a reply. It includes an example and a blank row. No email is needed to use it. There is an optional prototype walkthrough for tutors who want a separate manual tracker.”

**Request form introduction:** “Tell us how you currently handle lesson changes and a suitable time zone. We will reply to arrange a 15-minute prototype walkthrough. Submitting this form does not confirm an appointment.”

**Acknowledgement:** “Thanks for requesting a walkthrough. We will reply within two working days to confirm whether the prototype fits your workflow and arrange a time. You can keep using the worksheet meanwhile.”

**Qualified first reply:** “Thanks for describing your lesson-change workflow. The prototype lets you maintain a pending list manually; it does not sync replies. If that still sounds useful, would either [actual available time] or [actual available time] work for a 15-minute demonstration?” The bracketed times must be filled from a real calendar before sending.

**Mismatch reply:** “The prototype is designed for tutors tracking changed lessons manually. It doesn't cover the workflow you described. The worksheet remains available, but I don't want to book a call for a tool that doesn't fit.”

**One proposed follow-up:** “Would you still like to arrange the walkthrough you requested? If not, no action is needed and I won't follow up again.” Send only within the requested interaction and chosen follow-up policy; this example authorizes no messaging.

## Owner, capacity and review

The founder checks new requests each working day and owns every pending row until closed or handed off explicitly. Four 15-minute conversations use one hour of call capacity. Administration has a separate two-hour cap; it is not hidden inside call time.

If requests exceed available slots, explain the next available timing instead of promising immediate access. A declined request or request to stop closes the sequence. Resource opens alone do not enter a contact sequence.

The next proposed review occurs after a seven-day exposure window plus enough time for each request to receive its promised response. Track the same stages, qualification rule and timestamps. Inspect relevance and response delays before looking at aggregate volume.

No results for B exist. Success is not a promised percentage: the question is whether the more specific resource produces relevant interest and whether the founder completes the promised handoff. If suitable people still reject manual maintenance, the next work belongs in product/offer discovery rather than a larger campaign.
